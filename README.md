# KVAS для Keenetic

KVAS — пакет Entware для **селективной маршрутизации**: домены, IP-адреса и сети из
`kvas.list` направляются в VPN-туннель, остальной трафик идёт обычным WAN-маршрутом.
Этот форк рассчитан прежде всего на KeeneticOS 5.x и AmneziaWG-интерфейсы `opkgtunNN`.

## Как это работает

1. dnsmasq резолвит домен из `/opt/etc/kvas.list` и добавляет его IPv4-адреса в ipset
   `KVAS_LIST`.
2. iptables помечает трафик к этим адресам меткой `0xd1000`.
3. `ip rule` с приоритетом `99` отправляет помеченный трафик в таблицу `1001`, где
   default route указывает на VPN-интерфейс.

Для AmneziaWG, который создаётся вне NDM, пакетный watcher восстанавливает правила,
таблицу и цепочку маркировки после переподключения туннеля или сброса firewall.

## Быстрый старт

На машине для сборки:

```sh
./build.sh                  # версия MAJOR.MINOR.PATCH берётся из VERSION
scp kvasec_*.ipk root@192.168.1.1:/opt/tmp/
```

На роутере (при SSH-порте 222 добавьте `-p 222`):

```sh
opkg install --force-reinstall /opt/tmp/kvasec_*.ipk
kvas setup
kvas add example.com
kvas test
```

После настройки основной список находится в `/opt/etc/kvas.list`. Добавление домена
пересобирает DNS/ipset-правила в фоне; для массовых изменений используйте
`kvas import <файл>` и затем `kvas update`.

## Релизы и обновление

Merge в `master` автоматически собирает IPK и публикует его как GitHub Release `latest`.
Стартовая версия — `1.2.0`; каждый следующий merge увеличивает PATCH-часть
(`1.2.1`, `1.2.2`, …), поэтому роутер увидит обновление при:

```sh
kvas upgrade
```

Для приватного репозитория на роутере требуется fine-grained GitHub PAT с правом
`Contents: read` в `/opt/etc/kvas.github.token` (права файла `600`). Обновление не
устанавливается автоматически: это намеренно остаётся явной командой администратора.

## Важные замечания

- Фактический DNS-listener KVAS — `127.0.0.1:9753`; LAN-запросы на порт 53
  перенаправляются туда NDM-хуком. Не ориентируйтесь только на старое поле
  `DNSMASQ_PORT` в `kvas.conf`.
- WebUI по умолчанию слушает только `192.168.1.1:8085` и принимает клиентов из
  `192.168.1.0/24`. Он управляет маршрутизацией и списками; не публикуйте его в интернет.
  Для нестандартной LAN перед запуском можно явно задать `MONITOR_BIND` и
  `MONITOR_ALLOW_RANGE` в формате socat `адрес:маска`.
- Первый пароль WebUI задаётся на его странице и должен содержать не менее 4 символов.
  После установки его нельзя перезаписать без входа; смена доступна по кнопке «Пароль» после
  аутентификации. Хеши старых установок MD5 автоматически мигрируют в SHA-256 при успешном входе.
- Вкладка «Мониторинг обхода» запускается только вручную. Она проверяет до 40 доменов из
  VPN-списка и недавних DNS-запросов, отдельно показывает домены «в VPN, но недоступен» и
  позволяет добавить недоступный домен в VPN-список одной кнопкой.
- Перед изменением NDM-хуков и таблицы `1001` прочитайте разделы 0–1 в `NOTES.md`.
