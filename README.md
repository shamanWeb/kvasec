# KVASEC для Keenetic

KVASEC — пакет Entware для **селективной маршрутизации**: домены, IP-адреса и сети из
`kvas.list` направляются в VPN-туннель, остальной трафик идёт обычным WAN-маршрутом.
Этот форк рассчитан прежде всего на KeeneticOS 5.x и AmneziaWG-интерфейсы `opkgtunNN`.

## Как это работает

1. dnsmasq резолвит домен из `/opt/etc/kvas.list` и добавляет его IPv4-адреса в ipset
   `KVAS_LIST`.
2. iptables помечает трафик к этим адресам меткой `0xd1000`.
3. `ip rule` с приоритетом `99` отправляет помеченный трафик в таблицу `1001`, где
   default route указывает на VPN-интерфейс.

Для AmneziaWG, который создаётся вне NDM, пакетный watcher раз в 10 секунд проверяет и при
необходимости восстанавливает правила, таблицу и цепочку маркировки после переподключения
туннеля или сброса firewall.

## Быстрый старт

### Установка последнего релиза прямо на роутере

На роутере с уже установленным Entware выполните одну команду от `root`:

```sh
curl -fsSL https://raw.githubusercontent.com/shamanWeb/kvasec/master/install.sh | sh
```

Если `curl` ещё не установлен, используйте имеющийся в Entware/прошивке `wget`:

```sh
wget -qO- https://raw.githubusercontent.com/shamanWeb/kvasec/master/install.sh | sh
```

Скрипт находит `latest` GitHub Release, скачивает IPK, проверяет SHA-256 (если он
опубликован в релизе) и запускает `opkg install --force-reinstall`. Для первой
установки после этого выполните интерактивную настройку:

```sh
kvas setup
```

Репозиторий и релизы публичные: токен GitHub не нужен. Не запускайте установщик из
непроверенной копии репозитория.

### Ручная установка из локальной сборки

На машине для сборки:

```sh
./build.sh                  # версия MAJOR.MINOR.PATCH берётся из VERSION
scp kvasec_*.ipk root@192.168.1.1:/opt/tmp/
```

На роутере (при SSH-порте 222 добавьте `-p 222`):

```sh
opkg install --force-reinstall /opt/tmp/kvasec_*.ipk
kvas setup
kvas add example.com
kvas test
```

После настройки основной список находится в `/opt/etc/kvas.list`. Добавление домена
пересобирает DNS/ipset-правила в фоне; для массовых изменений используйте
`kvas import <файл>` и затем `kvas update`.

## Релизы и обновление

Merge в `master` автоматически собирает IPK и публикует его как GitHub Release `latest`.
Стартовая версия текущей линии — `1.3.0`; каждый следующий merge увеличивает PATCH-часть
(`1.3.1`, `1.3.2`, …), поэтому роутер увидит обновление при:

```sh
kvas upgrade
```

Репозиторий публичный, поэтому `kvas upgrade` работает без токена GitHub. Обновление не
устанавливается автоматически: это намеренно остаётся явной командой администратора.

## Важные замечания

- Фактический DNS-listener KVASEC — `127.0.0.1:9753`; LAN-запросы на порт 53
  перенаправляются туда NDM-хуком. Не ориентируйтесь только на старое поле
  `DNSMASQ_PORT` в `kvas.conf`.
- WebUI по умолчанию слушает только `192.168.1.1:8085` и принимает клиентов из
  `192.168.1.0/24`. Он управляет маршрутизацией и списками; не публикуйте его в интернет.
  Для нестандартной LAN перед запуском можно явно задать `MONITOR_BIND` и
  `MONITOR_ALLOW_RANGE` в формате socat `адрес:маска`.
- Первый пароль WebUI задаётся на его странице и должен содержать не менее 4 символов.
  После установки его нельзя перезаписать без входа; смена доступна по кнопке «Пароль» после
  аутентификации. Хеши старых установок MD5 автоматически мигрируют в SHA-256 при успешном входе.
- Родительский контроль блокирует введённый домен и все его поддомены через dnsmasq. Он требует
  активный dnsmasq; при включённом AdGuard Home интерфейс покажет, что этот режим недоступен.
- Вкладка «Мониторинг обхода» запускается только вручную: отдельные кнопки проверяют весь
  VPN-список либо последние 100 DNS-доменов. Она отдельно показывает домены «в VPN, но
  недоступен» и позволяет добавить `*.domain` в VPN-список либо убрать домен из него одной кнопкой.
- Перед изменением NDM-хуков и таблицы `1001` прочитайте разделы 0–1 в `NOTES.md`.
